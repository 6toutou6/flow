# 改造为线性顺序流转工作流系统

## Context

当前系统是"并行表单收集"模型：模板=字段集合，任务下发=指派多人并行填报。用户实际需要的是**顺序流转工作流**：模板=有序流程节点链（如分散采购：下发→需求设计→执行设计→合同设计→签订合同→结束），每个节点有独立表单字段，任务按节点顺序流转，每步处理人填完表单后**指定下一节点处理人**，直到结束节点任务完成。

已确认设计决策：① 纯线性顺序流转（无分支）；② 每步动态指定下一处理人；③ 区分开始/中间/结束节点；④ 新增"任务处理"页供处理人填表流转。需同步更新 `readme.txt` 和 `flow_schema.sql`。

## 一、表结构改造（flow_schema.sql + 执行DDL）

先清空 flow_* 测试数据（当前是验证用的测试数据，非生产数据），再改造：

**改造表（ALTER）**
- `flow_template`：DROP `flow_mode`、`enable_repeat_submit`（顺序流转不需要；保留 enable_modify）
- `flow_template_field`：ADD `node_id bigint`（字段归属节点）+ 索引
- `flow_task`：ADD `current_node_id`、`current_handler_id`、`finished_node_count int default 0`、`total_node_count int default 0` + 索引(idx_current_handler)
- `flow_form_record`：ADD `node_id`、`task_node_id` + 索引

**新增表（CREATE）**
- `flow_template_node`：id, template_id, node_name, node_key, sort_num, node_type(1开始2中间3结束), assign_next(0/1), node_tips, create_time；索引(template_id,sort_num)
- `flow_task_node`：id, task_id, node_id, node_name, sort_num, node_type, handler_user_id, submit_status(0待处理1已处理), handle_time, next_handler_user_id, form_record_id, create_time；索引(task_id,sort_num)、(handler_user_id,submit_status)

**废弃**：`flow_task_user`（保留表和代码不删，停止使用，新流程用 flow_task_node）

**不变**：flow_form_data、flow_attachment、sys_user

## 二、后端改造

### 2.1 flowtemplate 模块（流程设计器后端）
- **新增** `FlowTemplateNode` entity + `FlowTemplateNodeMapper`(BaseMapper)
- **新增** `TemplateFlowSaveDTO`：`{templateId, nodes[{id,nodeName,nodeKey,sortNum,nodeType,assignNext,nodeTips,fields[]}]}`（替代 TemplateSaveDTO）
- **改造** `TemplateDetailVO`：`{template, nodes[{node, fields[]}]}`
- **改造** `FlowTemplateField`：加 `nodeId`
- **改造** `FlowTemplate`：去掉 flowMode、enableRepeatSubmit
- **改造** `FlowTemplateService`：
  - `getDetail(id)`：查 nodes(按sort_num) + fields(按node_id分组) 组装树
  - `saveFlow(dto)`（替代 saveFields，@Transactional）：校验(首节点=1/末节点=3/结束节点assignNext=0) → 删旧fields+旧nodes → 插新nodes+fields → version+1
  - `copy/delete`：连带 nodes+fields
- **改造** `FlowTemplateController`：新增 `PUT /flow-template/save-flow`；`/{id}` 返回 nodes 树

### 2.2 flowtask 模块（任务流转核心）★
- **新增** `FlowTaskNode` entity + `FlowTaskNodeMapper`(+XML联表查询)
- **改造** `FlowTask`：加 currentNodeId/currentHandlerId/finishedNodeCount/totalNodeCount
- **改造** `TaskCreateDTO`：`userIds[]` → `firstHandlerId`（首个开始节点处理人）
- **新增** `NodeSubmitDTO`：`{taskId, taskNodeId, formData[{fieldId,fieldKey,fieldValue}], nextHandlerUserId, attachments[]}`
- **新增** `MyTodoVO`、`TaskProgressVO`
- **改造** `FlowTaskService`：
  - `create(dto)`（@Transactional）：锁定版本 → 查模板nodes → 插task(currentNodeId=首节点,currentHandlerId=firstHandlerId,totalNodeCount=n) → 插首个task_node(handler=firstHandlerId,待处理)
  - `submit(dto)`（核心事务）：校验(当前处理人=登录用户/task进行中/currentNodeId一致/必填字段/非结束节点需nextHandlerUserId) → 插form_record(带nodeId/taskNodeId) → 批量插form_data → 插attachment → 更新当前task_node(已处理/handle_time/next_handler/formRecordId) → 查下一节点：有则插新task_node+更新task指针；无则task.status=2完成
  - `myTodo(form)`：联表查 handler_user_id=登录用户 且 submit_status=0 的task_node（XML）
  - `taskProgress(taskId)`：查该任务全部task_node(按sort_num) + 处理人姓名
  - `getDetail`：返回 task+taskNodes+currentNode信息
  - `end/cancel`：同时把未处理task_node标记作废
- **改造** `FlowTaskController`：新增 `POST /flow-task/submit`、`POST /flow-task/my-todo`、`GET /flow-task/progress/{taskId}`

### 2.3 flowdata 模块（数据后台改任务维度）
- `DataStatsVO` 改为：totalTasks/runningTasks/finishedTasks/myTodoCount
- `FormRecordListVO` 加 nodeName/handlerName
- `FlowFormRecordMapper.xml`：list联表 flow_task_node+flow_template_node+sys_user
- `FlowDataService`：stats改任务维度统计；list/detail带节点信息

### 2.4 配置
- `HouseApplication @MapperScan`：已含 flowtemplate.mapper/flowtask.mapper，新Mapper自动扫描，无需改

## 三、前端改造

### 3.1 流程设计器（formdesigner/index.vue 彻底改造）
三栏布局改为"节点链 + 节点字段"：
- **左栏(节点链)**：垂直节点列表，每项=节点名+类型徽章+字段数+上下移/删除；节点间↓箭头；"+添加节点"（默认中间节点，插到结束前）；首节点强制类型1、末节点强制类型3
- **中栏(画布)**：当前选中节点的字段列表（沿用原字段增删/排序/选中逻辑）+ 顶部字段库8类型点击添加
- **右栏(属性面板)**：上半=节点属性(名称/标识/类型/提示/是否指定下一处理人开关)；下半=选中字段属性(沿用原逻辑)
- **数据**：`nodes[{id,nodeName,nodeKey,sortNum,nodeType,assignNext,nodeTips,fields[]}]`，selectedNodeIndex/selectedFieldIndex
- **保存**：`saveTemplateFlow({templateId, nodes[]})`，前端校验首末节点类型

### 3.2 任务下发（taskdispatch/index.vue）
- 第三步由"批量选填报人"改为"指定首个节点处理人"（单选）：选人弹窗改 `@current-change` 单选，展示已选处理人卡片
- 提交 payload：`{templateId, taskName, taskDesc, startTime, endTime, firstHandlerId}`
- 移除 flowModeText 相关；模板卡片不再显示流程模式

### 3.3 任务处理页（taskprocess/index.vue 新增）★
- **我的待办表格**：getMyTodoList → 任务名/模板/当前节点/节点提示/下发时间/操作[处理]
- **处理弹窗(el-dialog 宽800)**：任务信息 + el-steps流转进度(已处理success/当前process/未处理wait) + 动态表单(按当前节点fields渲染text/textarea/number/date/radio/checkbox/file) + "指定下一节点处理人"单选(结束节点隐藏) + [保存草稿][提交并流转]
- **动态表单渲染**：抽 `FormFieldsRenderer.vue` 组件，根据 fieldType 渲染对应Element组件
- **提交**：submitTask({taskId, taskNodeId, formData, nextHandlerUserId}) → 成功后刷新待办
- **附件简化**：file/image字段第一版只存文件名文本输入（不实现真实文件上传到对象存储），后续扩展

### 3.4 数据后台（dataadmin/index.vue 改造）
