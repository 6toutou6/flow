# 线性顺序流转工作流系统｜完整方案（任务 → 期次 → 人员 模型）

## 一、系统概述

### 业务场景
管理员先**设计流程模板**：把一个业务（如"问题整改"）拆解为一条**有序的流程节点链**——下发 → 需求设计 → 执行设计 → 合同设计 → 签订合同 → 结束。每个节点配置自己要填写的表单字段。

管理员再**创建任务**（如"巡查问题整改"）：任务引入模板后，填写模板级配置信息（任务级字段值，如需求编号规则），配置下发周期（每周/每月/每季度/单次）与**任务人员**。

任务按周期**自动生成期次**（2026-08期次、2026-09期次、2026-10期次……），也可**手动新增临时期次**（不影响后续自动下发）。每个期次自动为任务人员每人创建一条独立提交任务，人员从"开始"节点开始按节点链顺序流转：当前节点处理人填完表单、提交时**指定下一个节点的处理人**，依此推进，直到"结束"节点任务完成。

> 本系统是**顺序流转工作流**：不是所有人同时填一张表，而是一步一步往前走，每步处理人不同、每步填的字段不同；任务内每名人员拥有独立流程链。

### 举个例子（巡查问题整改）
1. 流程管理员新建模板"整改流程"，设计 6 个节点：下发 / 需求设计 / 执行设计 / 合同设计 / 签订合同 / 结束
2. 创建任务"巡查问题整改"：选择该模板，填写模板配置信息（整改单位、整改时限等），配置周期"每月 1 号下发"，配置人员张三、李四
3. 点击"生成期次"：选"立即下发"→ 生成 **2026-08** 期次（8/1 已过则补发当期）；选"下一期次"→ 生成 **2026-09** 期次；期次名可修改
4. 系统为张三、李四各创建一条独立任务（从开始节点开始），期次截止 = 触发日 + 每期截止天数
5. 张三登录 → 任务处理页 → 待办 → 填写下发节点表单 → 指定下一节点（需求设计）处理人 → 提交
6. ……依此流转，直到"结束"节点处理人提交，该人员任务变为"已完成"
7. 需要时可在任务中**手动新增临时期次**（不影响后续每月的自动下发）

### 角色定义
1. **超级管理员**：用户管理、角色权限、基础配置
2. **流程管理员**：创建流程模板、设计节点链与节点表单、创建任务、配置周期与人员、生成期次、查看流转数据
3. **处理人**：在任务处理页接收当前节点的待办，填写本节点表单、指定下一节点处理人后提交

### 核心能力清单
1. 流程模板管理（启用/停用、版本管理、复制）
2. **流程节点链设计**：可视化添加/排序节点，区分开始节点 / 中间节点 / 结束节点
3. **节点级表单设计**：每个节点单独配置要填写的字段
   - 字段类型：单行文本、多行文本、数字、日期、单选枚举、多选枚举
   - 字段属性：标签、占位文字、是否必填、排序、提示文案、最大长度
4. **任务管理**：任务引入模板 → 填写模板配置信息（任务级字段值，生成期次时抄用）→ 配置周期与人员
5. **期次生成**：自动（按周期 + 立即下发/下一期次）或手动临时期次；每期次自动为任务人员创建独立提交任务，期次名可修改
6. 任务处理：处理人在待办里填写当前节点表单，提交时指定下一节点处理人
7. 流转进度可视化：el-steps 展示任务走到哪一步、谁处理过、当前谁处理
8. 数据后台：任务管理页**折叠面板**展开任务查看期次，点「查看人员」直达该期次人员，再下钻到流程详情

## 二、总体架构分层
1. **前端（Vue.js + Element UI）**
   - 流程设计器：节点链 + 节点字段画布 + 属性面板
   - 任务管理：**独立编辑页**（单页全展示，不做分步：基本信息/模板配置信息/下发配置/任务人员一屏配齐）+ 任务列表**折叠面板**（展开查看期次、生成期次内嵌人员确认）+ **下发配置模板管理页**（维护常用配置库，新建任务一键拉取）
   - 任务处理：我的待办 + 处理弹窗（动态表单 + 指定下一处理人 + 流转进度）
   - 数据后台：任务管理页直达期次人员 → 流程详情
2. **后端（Spring Boot + MyBatis-Plus）**：模板/任务/期次/流转核心事务
3. **存储**：MySQL（业务结构化数据）

## 三、核心功能详细设计

### 3.1 流程模板模块
1. 新增/编辑/复制/删除模板（基础信息：模板名称、分类）
2. **设计流程**（核心）：三栏布局
   - 左栏「节点链」：垂直节点列表，每项 = 节点名 + 类型徽章 + 字段数 + 上下移/删除；首节点强制为"开始"、末节点强制为"结束"
   - 中栏「字段画布」：当前选中节点的字段列表，可增删/排序
   - 右栏「属性面板」：上半 = 节点属性（名称/类型/提示/节点填写说明），下半 = 选中字段属性
3. **保存流程弹窗**：保存方式二选一——「保存到当前版本」（覆盖，版本号不变）/「保存为新版本」（版本号+1，旧配置归档到版本记录表），可选填改动说明
4. **版本记录**：设计器头部可查看历史版本，版本快照存于 flow_template_version.config_snapshot
5. 模板启用/停用（已下发任务锁定当时版本）

### 3.2 任务管理模块（任务 → 期次）
模板 ≠ 任务 ≠ 期次（模板是图纸，任务是长期的工作项，期次是每轮收集）
1. **创建/编辑任务**（独立页面，非弹窗，三步向导）：
   - 基本信息：任务名称、任务说明、选择流程模板（仅启用的），并**填写模板配置信息**（模板级字段值，任务级配置）
   - 下发配置：周期类型（1每周 / 2每月 / 3每季度 / 4单次）、触发日（周几/每月几号）、每期截止天数、提前催办天数；顶部可**从下发配置模板一键拉取**（选中模板自动填充，可再微调）
   - 配置人员：多选任务人员（后续可随时变更）；保存后返回任务管理页
1-1. **下发配置模板管理**（任务管理页右上角入口）：
   - 维护一套常用下发配置库（配置名称/周期/触发日/截止/催办/备注），新增、编辑、删除
   - 模板新增/编辑为**独立设计页**（不做弹窗）：分区展示「基本信息 / 触发规则 / 截止规则 / 催办规则」，实时预览**下期触发、下期截止、提前提醒**日期，通俗易懂
   - 新建/编辑任务时在"下发配置"步骤选择模板即可**一键拉取**，避免反复配置导致错误
   - 删除模板不影响已拉取到任务上的配置（任务保存时复制一份到 flow_dispatch_config）
2. **任务管理页（折叠面板）**：
   - 每行一个任务（el-collapse 折叠面板），标题含任务名 / 状态 / 周期 / 期次数 / 人员数
   - **展开任务**显示：概览（模板/周期/截止催办/说明/**下一期次下发时间**/配置人员）+ 操作行（生成期次/编辑/停用启用/删除）+ **期次列表**（期次名/成员数/状态/起止时间/下发时间/查看人员/删除）
   - 期次列表**懒加载**：展开时才请求该任务的期次、下一期次预览与配置人员
3. **生成期次**（弹窗）：
   - **按周期自动下发**：先调 preview-period 预览期次（序号自动+1、默认期次名、起止时间）；「立即下发」= 当期次（触发日已过则补发当期，如 8/1 触发、8/6 补发 → 期次 2026-08），「下一期次下发」= 下一期次（2026-09）；期次名称可修改
   - **手动临时期次**：期次名必填，不影响后续自动下发编排
   - **人员确认区**：弹窗内展示本期次人员列表（默认抄用任务配置人员），可**临时增加/删除**（memberIds 临时人员仅影响本期次，不改任务配置）；确认为每位人员创建独立提交任务（从开始节点开始）
   - **起止时间**：开始 = 触发日（手动=现在），截止 = 开始 + 每期截止天数（补发且已过期则从今天起算）
4. 任务启用/停用：停用后不可再生成期次；删除任务仅当任务下无任何期次时允许

### 3.3 任务处理模块（流转核心）
1. **我的待办**：查询当前登录用户作为处理人、且未处理的任务节点
2. **处理弹窗**：
   - 任务信息 + 完整流程链（横向：已通过绿 / 处理中红 / 退回黄 / 未到灰，点击已处理节点展开详情）
   - **节点填写说明**：设计器配置的节点填写文字与说明文件在处理端展示
   - 动态表单：根据当前节点的字段配置渲染对应输入组件
   - **通过/退回确认弹窗**：防误点二次确认；退回时选择目标节点+原因，表单回填上次数据可修改重交
   - 右侧**操作历史**时间线：完整通过/退回记录（节点/处理人/时间/意见）
   - 提交并流转：指定下一节点处理人（结束节点提交即完成）
3. 提交校验：当前处理人=登录用户、任务进行中、节点一致、必填字段、非结束节点需指定下一处理人
4. 通过/退回时写入**流转日志**（flow_task_log.log_type=1）

### 3.4 数据管理模块（任务管理页直达）
1. 统计卡：任务总数 / 期次总数 / 进行中期次 / 我的待办
2. **任务列表**：任务名称（含说明）/ 流程模板 / 周期 / 触发日 / 期次数 / 人员数 / 启用状态 / 创建时间；点「查看期次」进入该任务期次列表（保留菜单入口）
3. **期次人员**（任务管理页点「查看人员」携带 dispatchId 直达，不走层级导航）：期次名称/所属任务/模板/截止时间/状态/成员数/成员状态概览/下发时间；成员卡片展示当前处理人/当前节点/进度/节点链，进行中成员可**催办**（二次确认，写入 flow_task_log.log_type=2），支持新增人员/批量删除；空期次可删除
4. **流程详情**：成员流程链 + 各节点表单数据 + 操作记录；返回按钮回到期次人员/任务管理页

## 四、数据库表设计（MySQL，InnoDB，主键统一 bigint）

> 设计原则：模板元数据与业务填报数据分离，动态表单不新增数据表，采用 JSON 存储字段配置；**任务配置与期次数据分离**——flow_dispatch 存任务配置（含模板配置信息与周期），flow_task_dispatch 存期次，flow_task 存每名人员的提交任务。

### 表1：sys_user 用户表
账号、员工号、姓名、部门、密码、状态。

### 表2：flow_template 流程模板表
模板名称、分类、版本号、状态、创建管理员、时间。

### 表3：flow_template_node 流程节点表【核心】
存储模板的节点链定义。
```
id, template_id, node_name, sort_num,
node_type(1开始 2中间 3结束),
node_tips, create_time
索引 (template_id, sort_num)
```

### 表4：flow_template_field 模板表单字段表
每个节点的字段配置，带 node_id（字段归属节点）。
字段：template_id、node_id、field_key、field_label、field_type、sort_num、required、placeholder、field_tips、max_length、enum_options(json)、field_role(1创建人填写/2处理人填写)。

### 表5：flow_dispatch 任务表【任务配置】
一个任务 = 一套模板配置 + 周期配置 + 人员配置，按期次抄用。
```
id, template_id, template_data(模板级字段值JSON，任务级配置，生成期次时抄用),
task_name, task_desc, period_type(废弃保留),
status(0停用 1启用), creator_id, create_time, update_time
```
说明：周期类型/触发日/截止/催办已迁出到 flow_dispatch_config（每任务一份），见下表。

### 表5-1：flow_dispatch_config 任务下发配置表【每任务一份】
周期配置独立建表，任务创建/编辑时一次性写入，长期复用。
```
id, task_id(唯一，每任务一份), cycle_type(1每周 2每月 3每季度 4单次),
cycle_day(触发日：周1-7/月1-31), deadline_days(截止天数), urge_days(催办天数),
create_time, update_time
```

### 表5-2：flow_dispatch_config_template 下发配置模板表【配置库】
管理员维护一套常用下发配置，新建/编辑任务时一键拉取填充到任务的 flow_dispatch_config。
```
id, config_name(配置名称), cycle_type, cycle_day, deadline_days, urge_days,
remark(备注), create_time, update_time
```
删除模板不影响已拉取到任务上的配置。

### 表6：flow_task_member 任务人员配置表【新增】
任务配置的人员，生成期次时批量抄用；后续可变更。
```
id, task_id, user_id, create_time
唯一键 (task_id, user_id)
```

### 表7：flow_task_dispatch 期次表【期次】
任务按周期自动或手动生成的每一期。
```
id, task_id(所属任务), template_id, template_version,
period_no(期次序号), period_name(期次名，如 2026-08),
manual_flag(0自动下发 1手动临时期次),
task_name, task_desc, template_data(抄用任务配置),
start_time, end_time, creator_id, create_time
索引 (task_id)
```

### 表8：flow_task 人员提交任务表
每名人员每期一条独立任务，从开始节点走完整流程。
```
id, dispatch_id(所属期次), template_id, template_version,
task_name, task_desc, template_data, start_time, end_time,
status(1进行中 2已完成 3已作废),
current_node_id, current_handler_id,
finished_node_count, total_node_count, creator_id, create_time
索引 idx_dispatch(dispatch_id)、idx_current_handler(current_handler_id)
```

### 表9：flow_task_node 任务流转节点表【核心】
任务实际流转记录，每个节点一条，记录处理人、处理状态、表单记录。
```
id, task_id, node_id, node_name, sort_num, node_type,
handler_user_id, submit_status(0待处理 1已处理), action(0通过 1退回),
handle_time, next_handler_user_id, form_record_id, create_time
索引 (task_id, sort_num)、(handler_user_id, submit_status)
```

### 表10：flow_form_record 表单填报主记录
每个节点处理人提交生成一条，带 node_id、task_node_id。
字段：task_id、template_id、node_id、task_node_id、user_id、record_status、is_draft、submit_time。

### 表11：flow_form_data 表单字段填写数据表
存储每个字段填写的值（文本/日期/数字/枚举值）。

### 表12：flow_attachment 附件文件表
统一管理上传文件。

### 表13：flow_template_version 模板版本记录表
保存"保存为新版本"时归档的旧配置快照。
```
id, template_id, version, version_desc, modifier_id, modifier_name,
config_snapshot(json：nodes+templateFields 完整配置), create_time
索引 (template_id)
```

### 表14：flow_task_log 任务流转/催办日志表
记录节点流转通知与催办动作，供追溯。
```
id, task_id, dispatch_id, task_node_id, node_id,
log_type(1流转通知 2催办), content, handler_user_id,
operator_id, operator_name, create_time
索引 (task_id)、(dispatch_id)
```

> 废弃：flow_task_user（旧表，新流程用 flow_task_node 承载处理人）

## 五、关键业务流程时序

### 流程1：管理员设计流程模板
1. 创建 flow_template（模板主表）
2. 设计节点链：添加节点（下发/需求设计/.../结束），设置节点属性
3. 为每个节点配置字段 → flow_template_field（带 node_id）
4. 保存流程：写 flow_template_node + flow_template_field，版本 +1

### 流程2：创建任务并配置
1. 新建任务 flow_dispatch：选模板、填任务名/说明、填模板配置信息（template_data）、配置周期与截止/催办
2. 配置任务人员 → flow_task_member（可随时变更）

### 流程3：生成期次
1. 自动：按周期预览（立即=当期/下一期次），计算 period_no、期次名、起止时间
2. 手动：期次名必填，start=now、end=now+deadline_days
3. 建 flow_task_dispatch（抄用任务配置）→ 为每位任务人员建 flow_task（current_node_id=开始节点）→ 建首个 flow_task_node（handler=该人员，待处理）

### 流程4：处理人提交并流转（核心事务 submit）
1. 校验：当前处理人=登录用户、任务进行中、current_node_id 一致、必填字段、非结束节点需 nextHandlerUserId
2. 插入 flow_form_record（带 node_id、task_node_id）
3. 批量插入 flow_form_data
4. 更新当前 flow_task_node：submit_status=1 已处理、handle_time、next_handler_user_id、form_record_id
5. 查下一节点：
   - 有下一节点 → 插入新 flow_task_node（handler=nextHandlerUserId，待处理）+ 更新 task 指针（current_node_id、current_handler_id、finished_node_count+1）
   - 无下一节点（已是结束节点）→ task.status=2 已完成
6. 下一节点处理人待办可见，循环直至结束

## 六、扩展点与优化建议
1. 权限细化、消息通知（站内信/企微/钉钉）
2. 分支流转：当前纯线性，后续可在节点配置分支条件
3. 表单联动：字段显隐联动规则
4. 数据导出：表单数据 + 附件打包下载
5. 期次自动定时下发：目前由管理员手动"生成期次"，后续可接定时任务按周期自动创建

## 七、潜在坑点提醒
1. 修改模板必须版本化，已下发任务沿用旧版本节点与字段
2. submit 流转必须事务化，避免节点记录与任务指针不一致
3. 并发提交需用 currentNodeId 一致性校验防止重复流转
4. 结束节点提交即完成任务，不再指定下一处理人
5. 模板节点链重建后，历史任务节点 ID 可能悬空，后端按 sort_num/node_name 逐级回退解析，任务节点详情需归一化到当前模板节点
6. 退回任务时表单数据需重置，并指定退回目标节点；通过/退回需二次确认防误操作

## 八、SQL 脚本说明（项目仅保留 2 个脚本）
