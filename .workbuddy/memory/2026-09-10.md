## 修复 back 仍返回任务处理页（hash 模式坑）

- 现象：上一版改完，从关联页进详情点返回，仍回任务处理页。
- 根因：路由是 **hash 模式**（`router/index.js:198` 的 `mode:'history'` 被注释）。`$router.resolve(...).href` 在 hash 模式下返回带 `#` 的 `#/flow-dispatch/task-link?...`；ProcessDetail `$router.push(back)` 推 `#` 开头的字符串会被 vue-router 当成「仅 hash 变化」，path 不变 → 落回默认任务处理页。
- 修复：TaskLink `openProcess` 改用 `$router.resolve(...).route.fullPath`（不含 `#`）；ProcessDetail `goBack()` 加防御，`back` 若以 `#` 开头则先 `slice(1)`。eslint 0 error。
- 结论（重要约定）：hash 模式下要拿可 push 的完整路径，用 `route.fullPath`，**不要用 `.href`**。

## 【设计讨论·未改代码】人员调动后历史期次不可见

- 难题：任务下发人员 A 处理多期后调走，后续期次改发给 B；B 看不到 A 处理过的期次（含在「新建关联」里选不到 A 的历史期次）。
- 根因（已核实）：
  - 「我的任务」按 `flow_task_node.handler_user_id = 当前登录人` 过滤（`FlowTaskNodeMapper.xml` selectMyTodo/selectMyTaskGroups/selectMyTodoByTasks 全部如此）。
  - 下发期次时**逐人**创建 `flow_task`（`FlowDispatchService.launchPeriod` 944-976 行），handler=当期人员；期次本身（`flow_task_dispatch`）**不存人员名单**，只能靠 `flow_task` 反查。
  - 任务人员配置 `saveMembers`（488 行）是**全量覆盖**（先 delete 再 insert），不留任何交接痕迹。
- 候选方案：
  1. **交接关系表 `flow_task_handover`**（推荐）：task_id + from_user + to_user + 生效期次；名单变更时登记；「我的任务」查询改为 `handler IN (我 + 我的前手链)`，历史期次对 B 只读展示。精准、权限可控。
  2. **按任务配置名单展示全期次**：查询改为按 `flow_dispatch` 当前名单匹配，B 看到该任务所有期次（A 的只读）。简单，但多人任务（A、C 并存）会越权看到他人期次，需额外按期次人员过滤。
  3. **仅放宽关联选择范围**：不动「我的任务」，只在新建关联里允许选历史期次。治标，本质仍需先能拿到 A 的数据权限。
- 待用户确认：①B 看 A 的历史期次是只读还是也要能操作（退回/补交）；②一个任务是否可能同时多人；③交接范围是整任务还是自某期起；④A 账号调走后是否还在系统。
- 用户要求细讲方案二。已核对：「我的任务」5 处 WHERE 均按 `flow_task_node.handler_user_id = #{me}`（FlowTaskNodeMapper.xml:56/96/136/172/187）；名单 `flow_task_member` 全量覆盖（FlowDispatchService.java:490）；节点处理人下发时写死（:971）。方案二核心 = WHERE 放宽为 `handler=me OR COALESCE(d.task_id,t.id) IN (SELECT task_id FROM flow_task_member WHERE user_id=me)`，靠 `todo_status` 天然只读；零数据迁移。
- **方案二被用户否决（关键设计结论）**：用户反例——第1期没下发给A、第2-4期下发给A，方案二下A会看到第1期。根因是**粒度错配**：可见性锚点必须是**期次**，不能是任务配置。已确认 `flow_task_dispatch`（期次表）**无处理人字段**；人员只在 `flow_task_member`（任务配置级当前名单）和 `flow_task.current_handler_id`（成员×期次实例，逐期精确）。
- **正确方向（期次级）**：①路线一「换人时迁移归属」——把 A 名下要交接的期次 `flow_task.handler` 改成 B，可加 `origin_handler_id` 留痕；查询不用改。②路线二「交接关系表 `flow_task_handover`」——from/to + 期次范围，可见性 = `handler=me OR 我=某交接to_user且期次在范围内`；不改原数据、可审计、可回滚，但查询多一层（链式需递归）。
