## ⚠️ 服务反复被回收 —— 改用 nohup 启动

今天前后端**三次**被回收，排查结果：
- 后端日志显示 `10:55:22 ... GracefulShutdown`（是被优雅关闭，不是崩溃）—— 用 `run_in_background` 起的进程会**随对话轮次结束被回收**；
- 前端有一次因 9528 仍被旧进程占用，dev server **自动漂到 9529** 端口，导致 curl 9528 拿到 200 但其实是旧进程（排查时容易被骗）。

**对策（已验证可用）**：改用普通 Bash 调用 + `nohup ... & disown`，让进程脱离会话：

```bash
cd flow-service && nohup env -u SERVER__PORT mvn spring-boot:run > /tmp/flow-backend.log 2>&1 & disown
cd flow-front   && nohup npm run dev > /tmp/flow-front.log 2>&1 & disown
```

启动后**务必确认端口**：`grep -i "Local:" /tmp/flow-front.log`，看到 `http://localhost:9528/` 才说明没漂到别的端口。

## 修 bug：从「期次任务关联」返回后任务面板被收起

皇上反馈：「点击期次的关联，跳转过去之后再返回，把我任务管理的自动收起来了，和其他页面不太一样」。

**根因不在返回，而在跳出去的入口**。`flowdispatch/index.vue` 的展开状态恢复机制是 `restoreExpandState()`（`created` 时调用），它只在 `sessionStorage.flowDispatchJumpOut === '1'` 时才恢复 `flowDispatchExpanded` 里的面板，然后消费掉标记。而**写标记的动作要靠各跳转出口自觉调用** `saveFlashId(id, dispatchId)`（内部会一并写 JumpOut + Expanded + Flash + FlashPeriod）：

| 跳转出口 | 修复前 |
|---|---|
| `openEdit(t)` | ✅ 有 `saveFlashId(t.id)` |
| `openPersonView(t)` | ✅ 有 `saveExpandState()` + `saveFlashId(t.id)` |
| `openPeriodUsers(t, p)` | ✅ 有 `saveFlashId(t.id, p.dispatchId)` |
| **`goTaskLink(t, p)`** | ❌ **漏了** ← 皇上报的 |
| `openCopyTask(t)` | ❌ 漏了（同类） |
| `openCreate()` | ❌ 漏了（同类） |

**修复**：
1. `goTaskLink` 加 `this.saveFlashId(t.id, p.dispatchId)`；`openCopyTask` 加 `this.saveFlashId(t.id)`；`openCreate` 加 `this.saveFlashId()`；
2. `saveFlashId` 支持 **id 可空**（新建任务没有来源任务）：`if (id) setItem(...) else removeItem(...)`，`dispatchId` 同理；
3. **顺带修一个既有 bug**：`restoreExpandState()` 里 `Number.isInteger(flashId)` / `Number.isInteger(flashPeriod)` —— `sessionStorage.getItem` 返回的是**字符串**，这判断**永远为 false**，所以「返回时红色双闪、期次行高亮」这两个效果从来没生效过。改成 `if (flashId && this.activeTasks.indexOf(flashId) >= 0)` 与 `if (flashPeriod)`（`activeTasks` 存的就是字符串 id，模板里 `flashTasks.indexOf(t.id)`、`flashPeriod === p.dispatchId` 也都是字符串比较，口径一致）。

**验证（agent-browser 实测走了一遍）**：
1. 进任务管理 → 点开「赵六关联任务测试」面板 → 点某期次的「关联」；
2. 查 `sessionStorage`：`flowDispatchJumpOut=1`、`flowDispatchExpanded=["FLOWD202609141648302135863970677"]`、`flowDispatchFlash`/`flowDispatchFlashPeriod` 都有值 ✅（修复前这几项为空）；
3. 点跳转页的「返回」→ 回到任务管理：`panels:2, open:1`（**面板保持展开** ✅，修复前为 `open:0`），`flowDispatchJumpOut` 已被消费为 null ✅；截图确认面板仍是展开态。

**踩坑记录**：agent-browser 的 `snapshot -i` 给出的 ref 有时点不动（`click e106` 无效），改用 `eval` 里 `document.querySelectorAll('button')` 找元素 `.click()` 才成功；另外同一页面连续 `eval` 会共享上下文，重复 `const`/`let` 声明同名变量会报 `Identifier has already been declared`，**一律用 `var` 或换名**。
