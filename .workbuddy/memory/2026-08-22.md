## 修复：模板管理页"暂无模板"（14:00，根因：status 空字符串过滤）
- **症状**：张三登录模板管理页显示"暂无模板，共计 0 条"，但后端接口不带 filters 返回 2 条、浏览器重登后页面正常
- **根因**：`FlowTemplateService.getPage` 的 status 过滤用 `eq(form.getStatus() != null, ...)`——前端默认传 `status:""`（空字符串），`"" != null` 为 **true** → 生成 `status = ''` 条件 → 全部模板被过滤成 0 条
- **修复**：`!= null` → `StringUtils.hasText(form.getStatus())`（空字符串不生成条件）
- **排查教训**：String 类型查询字段空值判断一律用 hasText，不能 `!= null`；其他模块（FlowDispatch/FlowTask 走 XML OGNL when 判断、UserQueryForm.status 是 Integer）无此问题
- **注意**：重启后端会使所有会话失效，浏览器需重新登录

## 重构遗留报错逐页排查修复（14:21，浏览器实测）
**共修复 5 类重构遗留 bug**：
1. **UserController.search**：`String.valueOf(params.get("userName"))` 当值为 null 时得到字符串 "null" → `LIKE '%null%'` 查不到 → **所有 UserPicker 选人弹窗列表为空**（选处理人/选管理员全挂）。修：先判 null

3. **FlowDispatchService**：`dto.getStatus() == 1` 数字比较 → 新增 `normalizeStatus()` 归一化（null/"1"/"0"/"启用"/"停用" → 中文）
4. **XML status 空串过滤**：FlowDispatchMapper.xml(selectTaskPage/selectTaskCount)、FlowTaskMapper.xml(成员列表) 的 `<if test="status != null">` → `status != null and status != ''`（前端默认传 status:"" → `AND d.status=''` → 列表 0 条，与模板列表同款 bug）

**排查经验**：String 状态字段的空值判断必须 hasText/`!= ''`；`!= null` 对空字符串为 true 是高频坑（已出现 3 次）；agent-browser 的 ref 点击在弹窗/异步组件内不稳定，改走 vm 实例方法或 .click() 更可靠；hash 导航带 /login 前缀时不生效，需刷新或 $router.push
