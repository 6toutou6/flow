## 走读（未改代码）：期次「新增人员」的「已存在」判定口径

**皇上问题**：任务「zqk测试任务-任务整改」· 期次「新增功能-测试」，新增人员赵六时提示「所选人员均已在该期次中，无需重复新增」，这块逻辑是怎么判断的。

**判定链路**：
1. 前端 `PeriodUsers.vue` 的 `onAddMembers()` → `addPeriodMembers(dispatchId, userIds)`，**前端不做任何预判**；
2. 后端 `FlowDispatchService.addPeriodMembers()`（约 1028-1077 行）：
   - 先取该期次下所有成员任务 id：`flowTaskMapper.selectList(eq(FlowTask::getDispatchId, dispatchId))`
   - 再把这些任务的**所有节点处理人**收进 `existing`（`flow_task_node.handler_user_id` 去重）
   - 逐个 uid：`if (existing.contains(uid)) continue;` 都不新增时 `count == 0` → `throw new RuntimeException("所选人员均已在该期次中，无需重复新增")`
3. 提示由 `handleResponse` 弹出（message 即后端的这句）。

**为什么赵六被误判（数据佐证）**：
- 该期次下 3 个成员任务，`owner_id` 只有 **张三(emp0001)×2、王五(emp0003)** —— 赵六不是成员；
- 但赵六是「技术部-张三的问题整改处理」里**「问题整改」(sort=1) 与「行领导审核」(sort=4) 两个节点的处理人**（均已完成），所以落进了 `existing`；
- 该配置的 `flow_task_member` 名单也只有 张三/李四/王五，**没有赵六**；
- 于是 `existing = {张三, 李四, 王五, 赵六, 周九}`，新增赵六命中 → 拒绝。

**口径冲突（根因）**：注释写的是「该期次已存在的人员（从节点处理人判定，避免重复新增）」，但**用「节点处理人」代替了「成员」**。只要某人在该期次任意任务的任意节点上被指为处理人（协同处理、被指定为下一节点处理人、增加处理人），就会被当成"已在该期次中"；而真正的成员归属应以 `flow_task.owner_id`（或 `flow_task_member`）为准。

**皇上纠正了口径（2026-09-14 上午）**：「下发的时候，判断是否重复，是根据**第一个处理人**的，跟其他的都没有关系」。数据核对后确认皇上的口径正确，且**臣上一轮建议的「改用 owner_id」是错的**：

- 按「第一个节点（sort 最小）的处理人」口径，该期次 `existing = { 张三 emp0001 · 李四 emp0002 · 王五 emp0003 }`，**赵六不在其中** → 应放行 ✅
- 但 `flow_task.owner_id` **不可靠**：`市场部-李四的问题整改处理` 这条任务的 `owner_id = emp0001 张三`（创建人），而它的第一个处理人是 `emp0002 李四` —— 两者不一致，用 owner 判定会把李四漏掉、并可能误放行张三。另两条任务（张三/王五）owner 与首处理人一致，属"碰巧对"。
- 结论：判定必须取**第一个节点的处理人**，不能取 owner，也不能取"所有节点处理人"（现实现的 bug）。

**修改方向（皇上尚未指示是否动手）**：`FlowDispatchService.addPeriodMembers()` 里收集 `existing` 的那段 —— 现在是一次 `selectList(in(taskId, taskIds).select(handlerUserId))` 把**所有节点**处理人全收进来；应改为**每个任务只取 sort_num 最小的那个节点的 handler**（查询时带上 `taskId` / `sortNum`，按 taskId 取最小 sort 那条）。
- 边界提醒：若成员把自己第一个节点**交接**出去，按此口径他就不再算"在期次中"、可被再次新增 —— 需皇上确认是否接受（皇上原话是"跟其他的都没有关系"，倾向接受）。

## 澄清：「已收集 0/1 份」里那个 1 是什么（皇上追问）

**结论：当前语义是「这条关联指向的那一条成员任务完成了没」，不是「期次里有多少人」。**

后端 `FlowTaskLinkService.toVO()` 有两条互斥分支：
1. **任务级**（link 的 `target_task_id` 有值）→ `memberCount = 1`（写死），`doneCount = TASK_DONE.equals(tt.getStatus()) ? 1 : 0` —— 只盯这一条任务；
2. **期次级**（`target_task_id` 为空，回落到期次聚合）→ `memberCount = 该期次下 flow_task 数`，`doneCount = 其中 status=已结束 的数`。
